- **Multi-photo posts now download ALL photos as a ZIP (user bug report: "sirf first photo deta hai").** `src/lib/facebook.ts`: `extractPhotoFromHtml()` → `extractPhotosFromHtml()` — collects EVERY candidate URL from the page (og:image first, then every `"image":{"uri":…}` JSON blob = one per sibling photo, then scontent/fbcdn `<img>` srcs), promotes each to full-res (`promotePhotoUrl`: `stp=dst-jpg_s…`→`p2048x2048`, `/p\d+x\d+/`→`/p2048x2048/`), dedupes by **URL path** (same photo at 4 sizes collapses to one; different `_nc_cat`/`oe`/`oh` params don't duplicate). New skip rules: `static.` hosts + `rsrc.php` (emoji sprites — never photos) and `/p\d{1,2}x\d{1,2}/` small paths (avatars p40x40 etc.); existing `s\d+x\d+`/`emoji`/`avatar`/`profile_image` skips kept. `fetchFacebookPhotoSet(url)` (memoSWR `fb:photos:{url}`, same 4-way parallel matrix, keeps the page with the MOST photos) returns `{photos: FacebookPhoto[], title, cover, author}` capped at `MAX_PHOTOS_PER_POST = 50`; `fetchFacebookPhoto` is now a thin wrapper returning `photos[0]` (single-download path unchanged). Verified: node test → Windows `Expand-Archive` extracts entries byte-identical.

GET `dl=zip` → bundles ALL photos via `buildZip`, `Content-Type: application/zip`, `Content-Disposition: attachment; filename="tiksavehub-facebook-photos.zip"` + `Content-Length`; falls back to fresh fetch when cache lacks ≥2 photos; structured 500 JSON if all downloads fail.
